# Directed-modularity verification phase 5: wire the directed value-oracle

## Execution plan: Phase 5 of the directed-modularity verification project

Self-contained plan for an executing agent. All prior open questions are resolved
(the decisions are recorded in Section 2 and woven into the tasks). It implements
Phase 5 ("wire the directed value-oracle") of the research plan in
[docs/research/directed-modularity-formal-verification.md](../docs/research/directed-modularity-formal-verification.md),
tracked by ticket `mes-43lb` (parent epic `mes-crz3`). It builds on Phases 1-4:
the directed objective and its rational mirror (Phase 1), the objective identities
(Phase 2), the guarantee triage (Phase 3), and the formalized survivors (Phase 4,
`mes-jlz8`).

## 1. Context and inputs

`meso` is a pure-Go community-detection library whose undirected numeric core is
validated end to end against a **Lean value-oracle**: the `mesoOracle` executable
evaluates computable rational mirrors of the objective and the guarantee
predicates, emits exact golden vectors, and the Go tests assert their float64
results against those proved values within a ULP tolerance. Phase 5 extends that
loop to directed graphs.

What the prior phases delivered that Phase 5 consumes:

- **Phase 1 (`Meso/DirectedCompute.lean`, proved):** the computable rational
  mirror `DirectedWeightedGraphQ`, `directedModularityQ`,
  `moveDeltaDirectedModularityQ`, the F2 equivalences `directedModularityQ_eq` /
  `moveDeltaDirectedModularityQ_eq`, `DirectedWeightedGraphQ.ofRaw` (no
  symmetrization), and five machine-checked fixture values on a 3-node asymmetric
  graph.
- **Phase 2 (`Meso/DirectedAggregate.lean`, `Meso/DirectedMove.lean`, proved):**
  the objective identities (aggregation invariance, the closed-form move-delta).
- **Phase 4 (`Meso/Directed{Convergence,Connectivity,Separation,SubsetOptimality}.lean`,
  proved):** the surviving guarantees as **real-valued Props**: weak connectivity
  (`directedConnectedCommunities_of_refineRun` over
  `DirectedWeightedGraph.simpleGraph`), γ-separation conditional on directed level
  stability (`directedGammaSeparated_blockWeight_of_levelStable`), and the subset
  bound conditional on directed subset stability
  (`directedSubsetGammaDense_of_subsetStable`). Phase 4 deliberately produced **no
  computable Bool mirrors** and touched no oracle code; those mirrors are this
  phase's first block of work (decision D1).
- **Phase 3 (`docs/research/directed-modularity-triage.md`):** the verdicts, the
  n=4 subset-refutation fixture, and the exact directed bounds.

The undirected oracle this phase mirrors:

- `Meso/Compute.lean` (rational objective mirrors), `Meso/Predicates.lean`
  (decidable Bool mirrors + `..._iff` equivalences), `Meso/OracleIO.lean` (the
  parser/evaluator/printer), `Main.lean` (the `mesoOracle` entry point).
- `datasets/*/*.gml` (committed Newman-format source graphs),
  `verification/oracle/tools/gml_to_input.py` (GML to input converter),
  `verification/oracle/inputs/*.json` (committed inputs),
  `verification/oracle/golden/*.json` (committed golden vectors, regenerated by
  `make oracle-lean`).
- Go harness: `oracle_test.go` (loader + tolerance + `goQuality`/`goDelta`),
  `oracle_harness_test.go` (value/delta/predicate load tests), `guarantees_test.go`
  (the Go predicate deciders and the `TestOracle_*Vector` tests that assert them
  against the golden flags).

## 2. Resolved decisions (settled with the user)

- **D1 (mirror ownership).** The directed Bool mirrors (Lean decidable predicates +
  `_iff` proofs) are owned by Phase 5, not a separate ticket. Update the research
  doc's phase descriptions so the Phase-4/Phase-5 boundary is official (Task 9).
- **D2 (subset flag).** Emit a directed `subsetOptimal` flag as a characterization:
  build the directed subset Bool mirror + `_iff`, emit the flag (gated by the node
  bound), and assert the Go decider against it. It reads `false` on the n=4 fixture
  (the documented limitation) and `true` elsewhere; the `_iff` holds regardless of
  whether the algorithm attains the hypothesis.
- **D3 (input schema).** Distinguish directed inputs with a top-level
  `"directed": true` flag on the existing schema. `edges` become single arcs
  (from -> to, listed once, not symmetrized), and `quality` must be
  `"directedModularity"`. The `make oracle-lean` glob and the harness loader stay
  unchanged; only `runFile`/`buildOracleGraph` branch on the flag.
- **D4 (predicate object shape).** Directed golden cases omit the `gammaDense` key
  (CPM-only); the directed predicate object is `{connected, gammaSeparated,
  subsetOptimal}`. The Go loader gets a directed predicate struct.
- **D5 (fixture design).** Follow the undirected shape: a few small directed graphs,
  each with multiple partition cases engineered so connectivity, γ-separation, and
  subset each get a true AND a false case across the set.
- **D6 (small fixture set).** Three small graphs (Section 5.3): `directed_asym3`,
  `directed_subset4`, `directed_cycles6`. No standalone single-arc-pair fixture
  (asym3 already provides a weakly-but-not-strongly connected community and a
  disconnected community).
- **D7 (corpus fixture).** Also add one real directed corpus fixture at scale:
  **celegansneural** (the C. elegans neural network, directed and weighted, ~297
  nodes), from the same Newman collection as the current corpus. Its subset flag is
  null (n > node bound); it exercises directed values, connectivity, and
  γ-separation at scale.
- **D8 (generator).** Add a `--directed` flag to
  `verification/oracle/tools/gml_to_input.py` (do not fork a new script): with the
  flag it honours the GML `directed 1` header, keeps arcs `source -> target` (no
  symmetrization), and sets `"directed": true` and `quality: "directedModularity"`
  in the emitted input.
- **D9 (ticket structure).** One ticket (`mes-43lb`), with a quantity-first task
  order so a green checkpoint (directed values + move-deltas verified) is reached
  before the predicate mirrors and corpus land.

## 4. Shape of the work: three tracks, quantity-first

Phase 5 has three tracks. The task order (Section 7) interleaves them so a
quantity-first checkpoint lands before the predicate proofs:

1. **Quantity oracle (glue).** Directed IO path in `OracleIO.lean` (the `directed`
   flag, `directedModularityQ`, `moveDeltaDirectedModularityQ`), the small directed
   value/delta fixtures, and the Go harness directed build path +
   `directedModularity` quality/delta case. This alone closes the Phase 1/2
   identities end to end and is the checkpoint (Tasks 1-3).
2. **Predicate Bool mirrors (new proofs).** `Meso/DirectedPredicates.lean`:
   decidable rational predicates over `DirectedWeightedGraphQ`, each proved `_iff`
   its Phase 4 real Prop on `.toReal`, mirroring `Meso/Predicates.lean`. The one
   substantial proof is the polynomial connectivity decider; the rest are short
   `Rat.cast` pushes. Then the directed predicate emission in `OracleIO.lean` and
   the Go predicate deciders + vector tests (Tasks 4-5).
3. **Corpus (scale).** The `--directed` generator flag and the celegansneural
   fixture, exercising values + connectivity + separation at ~297 nodes (Task 7).

## 5. Deliverables and design decisions

### 5.1 Lean: directed quantity IO (`Meso/OracleIO.lean`; Task 1)

The directed graph is a distinct type from `WeightedGraphQ`, so add a parallel
evaluation path, not a generalization:

- **Schema.** Parse an optional top-level `"directed": bool` in `parseInput`. When
  true, the only accepted `quality` is `"directedModularity"` (extend the quality
  parser / `QKind`, or carry a separate directed case type; update the `QKind`
  docstring that currently says directed is out of scope).
- **Directed graph build.** `buildDirectedGraph n edges sizes :
  DirectedWeightedGraphQ n` via `DirectedWeightedGraphQ.ofRaw`, same parallel-arc
  fold as `buildGraph` but **without** symmetrization (arc `i -> j` contributes only
  to `weight i j`).
- **Directed evaluators (quantities).** `evalDirectedQuality` =
  `directedModularityQ`; `evalDirectedDelta` = `moveDeltaDirectedModularityQ`.
- **Dispatch.** In `runFile`, branch on the parsed flag: directed path builds
  `DirectedWeightedGraphQ` and calls the directed evaluators; undirected path
  unchanged. Emit the same `{ provenance, n, cases }` envelope plus a top-level
  `"directed": true` so the harness can read it back. Predicates are added in Task 4
  (leave the directed predicate object empty or omitted until then, or land Task 4
  before regenerating goldens).

### 5.2 Lean: directed Bool mirrors (`Meso/DirectedPredicates.lean`; Task 4)

GPL header. Imports `Meso.DirectedCompute` (the ℚ graph), `Meso.DirectedConnectivity`,
`Meso.DirectedSeparation`, `Meso.DirectedSubsetOptimality` (the real Props to prove
`_iff` against), `Meso.Reachability` (the fast decider). Mirror `Meso/Predicates.lean`:

- **Rational directed block aggregates:** `directedBlockWeightQ`, `commOutDegreeQ`,
  `commInDegreeQ` over `DirectedWeightedGraphQ`, with `toReal_*` bridge lemmas
  (`toReal_totalWeight` already exists in `DirectedCompute.lean`; reuse).
- **G1 weak connectivity:**
  - `DirectedWeightedGraphQ.simpleGraph := SimpleGraph.fromRel (fun i j => 0 < G.weight i j)`
    - `DecidableRel .Adj` instance.
  - `toReal_directedSimpleGraph : G.toReal.simpleGraph = G.simpleGraph` (via
    `Rat.cast_pos`; both use `fromRel`, so it is the same graph-equality argument as
    `toReal_simpleGraph`).
  - `radjDirQ` + its `DecidableRel`, and `reflTransGen_radjDirQ_iff_reachable`
    (mirror `reflTransGen_radjQ_iff_reachable`).
  - `directedCommunityConnectedFast` (Bool, reachable-set closure) and
    `directedCommunityConnectedFast_iff`; then `DirectedConnectedCommunitiesFast`
    (Prop, Decidable) and `directedConnectedCommunitiesFast_iff :
    DirectedConnectedCommunitiesFast G p ↔ DirectedConnectedCommunities G.toReal p`.
    Mirror `connectedCommunitiesFast` / `..._iff` line for line.
- **G2 directed γ-separation:**
  - `DirectedGammaSeparatedCommunitiesQ G γ p : Prop` (Decidable): for all distinct
    occupied `C, D`,
    `directedBlockWeightQ G p C D + directedBlockWeightQ G p D C ≤
     γ * (commOutDegreeQ G p C * commInDegreeQ G p D
          + commOutDegreeQ G p D * commInDegreeQ G p C) / G.totalWeight`.
    Keep the `/ totalWeight`; ℚ division by zero is 0, matching the real side.
  - Real `DirectedGammaSeparatedCommunities G γ p` in the same shape over
    `directedBlockWeight` / `commOutDegree` / `commInDegree` / `totalWeight` (the
    "for all pairs" packaging of `directedGammaSeparated_blockWeight_of_levelStable`).
  - `directedGammaSeparatedCommunitiesQ_iff` (push `Rat.cast_le` through the
    bridges; `Rat.cast` commutes with `/` in ℝ, `Rat.cast_div`).
- **G3 directed subset bound (D2):**
  - `DirectedSubsetOptimalQ G γ p : Prop` (Decidable), enumerating each community's
    fiber powerset: for every occupied `C`, every subset `S` of its fiber (with
    `T = C \ S`), `γ * (KoutS * KinT + KoutT * KinS) / m ≤ e(S,T) + e(T,S)` in ℚ.
  - Real `DirectedSubsetOptimal G γ p` in the same shape, and
    `directedSubsetOptimalQ_iff` (mirror `subsetOptimalQ_iff`, including the empty /
    nonempty subset split and the `by_cases`).

Register in `Meso.lean` after `import Meso.Predicates`. Acceptance: `lake build
Meso.DirectedPredicates` green; no `sorry`; `#print axioms` on the three `_iff`
theorems shows only `propext`, `Classical.choice`, `Quot.sound`.

Then extend `OracleIO.lean` with `evalDirectedPredicates` emitting `{ connected,
gammaSeparated, subsetOptimal }` from `DirectedConnectedCommunitiesFast`,
`DirectedGammaSeparatedCommunitiesQ`, `DirectedSubsetOptimalQ` (last gated by
`maxSubsetOptimalN`, null above it); no `gammaDense` key (D4).

### 5.3 Small directed fixtures (Task 6)

Three input files under `verification/oracle/inputs/` (the `make oracle-lean` loop
globs `inputs/*.json`; no Makefile change). Node indices `0..n-1`; the harness
registers nodes in index order first, so no interning surprise. Include `"deltas"`
on the asym3 and subset4 cases. Choose partitions so each predicate gets both a
true and a false case across the set; verify exact branch coverage from the
generated goldens.

- `directed_asym3.json` - the Phase 1 3-node asymmetric graph (arcs 0->1:2, 0->2:1,
  1->0:1). Cases: partitions reproducing the `DirectedCompute.lean` hand-checked
  values (`[0,0,0]`, `[0,1,2]`, `[0,0,1]`) with move-deltas; a `[0,1,0]`-style
  partition whose community `{0,2}` has only the arc `0->2` (weakly connected =
  true, i.e. weak-not-strong); and a `[0,1,1]` partition whose community `{1,2}` has
  no arc either way (connected = false).
- `directed_subset4.json` - the n=4 triage graph (arcs 0->1:1, 0->3:1, 1->0:3,
  1->2:1, 1->3:5, 2->0:2, 3->2:5). Cases: all-in-one `[0,0,0,0]` at γ=1 (value 0 via
  `directedModularity_const`; subset flag **false** - the documented limitation);
  the `{0,1},{2,3}` split `[0,0,1,1]` (subset flag true; a γ-separation case).
- `directed_cycles6.json` - two directed 3-cycles + one bridge arc (the
  `twoDirectedCyclesGraph` shape from `directed_api_test.go`). Cases: the
  two-community partition (connected true, γ-separated true); a partition that
  groups across the bridge or all-in-one to yield a γ-separation **false** branch.

Note: the emitted γ-separation flag is the raw predicate value (the bound holds or
not), independent of whether the partition is level-stable; the fixtures only need
both branches, not stability. Regenerate goldens with `make oracle-lean`; commit
inputs and goldens.

### 5.5 Go harness (Task 3 quantities, Task 5 predicates)

- **Loader (`oracle_test.go`).** Add `Directed bool` to `inputFile` (from the input
  `"directed"` key) and `oracleFixture`. In `buildOracleGraph`, branch: directed uses
  `NewDirectedBuilder()`, still registering nodes `0..n-1` via `AddNodeWeight` first,
  then `AddEdge(from, to, w)` **once per arc** (no reverse). Add a directed predicate
  struct for the `{connected, gammaSeparated, subsetOptimal}` shape (D4). Keep a
  separate `directedOracleFixtureNames` list (`directed_asym3`, `directed_subset4`,
  `directed_cycles6`, `celegansneural`); do **not** add directed fixtures to
  `oracleFixtureNames` (the existing `TestOracle*` tests switch on
  modularity/cpm and build undirected graphs).
- **`goQuality`/`goDelta`.** Add a `"directedModularity"` case:
  `directedModularity{gamma}.Quality(g, p)` / `.moveDelta(g, p, node, target)`. The
  fixture graph must be a directed `csr`.
- **Directed predicate deciders (`guarantees_test.go`).**
  - `directedConnectedCommunities(g, p)` - weak connectivity: per community, traverse
    **both** `g.neighbors(u)` (out) and `g.inNeighbors(u)` (in) with positive weight,
    staying in the community. (The existing `communityConnected` uses out-arcs only;
    the difference is the whole point of "weak".)
  - `directedGammaSeparatedCommunities(g, gamma, p)` - the block bound
    `e(C,D)+e(D,C) <= gamma*(KoutC*KinD+KoutD*KinC)/m` over distinct occupied pairs,
    with per-community out/in degree sums and `m` the total arc weight.
  - `directedSubsetOptimalDecider(g, gamma, p)` - the directed subset bound over each
    community's subset powerset (mirror `subsetOptimalOracle`: two cross directions,
    the `/m` degree-product term).
- **Directed vector + load tests (`guarantees_test.go` / `oracle_harness_test.go`,
  or a new `directed_oracle_test.go`).** `TestOracle_DirectedQualityValues`,
  `TestOracle_DirectedDeltas`, `TestOracle_DirectedConnectivityVector`,
  `TestOracle_DirectedGammaSeparatedVector`, `TestOracle_DirectedSubsetVector`, and a
  `TestOracleLoadsDirected` tracer. Each iterates `directedOracleFixtureNames`,
  asserts the Go decider/quantity against the golden flag/value within tolerance,
  with two-sided teeth (subset4 supplies false subset; asym3 supplies false
  connectivity; a γ-sep false case supplies that branch). celegansneural's
  subsetOptimal is null and must be skipped, not read as false.

## 9. Risks and fallbacks

- **The connectivity fast decider port (Task 4, G1) is the one substantial proof.**
  It ports `communityConnectedFast_iff` and `reflTransGen_radjQ_iff_reachable`; the
  `Reachability` layer is reused unchanged, only the adjacency changes to the
  directed `simpleGraph` (still symmetric via `fromRel`). A ported step that fails is
  almost always a `simpleGraph`/`fromRel` definitional mismatch. Fallback: emit the
  flag from the exponential `Decidable (SimpleGraph.Connected _)` gated by a small
  node bound - but celegans (n~297) needs the fast decider, so budget the port.
- **The `/ totalWeight` in the γ-separation and subset predicates** needs the real
  predicate stated with the same division so `Rat.cast_div` closes the `_iff`. Keep
  both sides in `... / m`; do not pre-clear denominators (an `m = 0` fixture would
  then diverge from the `1/0 = 0` convention). All fixtures have `m > 0`, but the
  predicate must be defined at `m = 0`.
- **Undirected tests must not iterate directed fixtures.** Keep a separate
  `directedOracleFixtureNames`; a directed input in `oracleFixtureNames` makes
  `goQuality` hit an unknown-quality fatal or build the wrong graph. Most likely
  "green Lean, red Go" trap.
- **Go weak-connectivity decider must use both out- and in-neighbours.** Reusing
  `communityConnected` (out-only) would wrongly report some weakly-connected
  directed communities as disconnected, disagreeing with the proved flag.
- **celegansneural provenance/license.** Verify the GML is from the same public
  collection and committable under the project's posture before adding it; record
  the source. If the specific file is not cleanly licensable, fall back to another
  directed GML from the same collection (note the substitution).
- **Corpus oracle runtime.** Exact ℚ over ~297^2 pairs plus the polynomial
  connectivity decider should be seconds, but confirm `make oracle-lean` completes;
  if it is slow, that is a signal the connectivity decider is not the fast one.
- **Determinism.** The directed evaluators use only `directedModularityQ`/`decide`,
  no `Float`/ordering, so goldens are exact; re-running `make oracle-lean` must leave
  them byte-identical.
- **No mathlib cache / no network:** `make lean` may need the cache. If absent, stop
  and report rather than rebuilding mathlib.
